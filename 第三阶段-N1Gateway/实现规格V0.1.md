## 1. 交付边界

本规格把第三阶段总体设计落实为可直接编码的约束。G1 交付物是一个可安装到 N1 的独立 APK，以及电脑和 iPhone 可访问的只读状态页面。

G1 只允许以下蓝牙命令：

```text
GET_DEV_INFO
REGISTER_NOTIFICATION
READ_SETTINGS
READ_RF_CH
GET_HT_STATUS
GET_VOLUME
```

G1 不允许出现以下代码路径：

```text
SET_VOLUME
WRITE_SETTINGS
WRITE_RF_CH
SET_IN_SCAN
PTT 按下或释放
音频上传、下载、播放或录音
HT 云端登录或聊天室连接
固件升级或工厂复位
```

代码评审时，如果网页线程、HTTP 处理线程或 Activity 中出现可直接发送 GAIA 字节的方法，视为设计失败。

## 3. 清单与权限

Manifest 只申请 G1 必需权限：

```xml
android.permission.BLUETOOTH
android.permission.BLUETOOTH_ADMIN
android.permission.ACCESS_FINE_LOCATION
android.permission.INTERNET
android.permission.WAKE_LOCK
android.permission.ACCESS_WIFI_STATE
android.permission.CHANGE_WIFI_STATE
android.permission.RECEIVE_BOOT_COMPLETED
```

说明：

- Android 7.1 读取已配对设备和蓝牙连接需要定位权限。
- `INTERNET` 只用于本机或私有网络监听，不允许加入任何公网业务地址。
- `WAKE_LOCK` 用于前台服务运行期间的屏幕唤醒锁、部分 CPU 唤醒锁和 Wi-Fi 高性能锁。0.3.4 首次升级默认开启屏幕常亮；0.3.3 实测表明仅持有 CPU/Wi-Fi 锁不能让该 N1 固件在熄屏后保持联网。屏幕锁只用于网关常驻，不代表允许发射。
- `ACCESS_WIFI_STATE`/`CHANGE_WIFI_STATE` 只用于持有高性能 Wi-Fi 锁，避免 N1 熄屏后关闭网络；服务停止时立即释放。
- 不申请存储、麦克风、相机、电话、后台定位、悬浮窗或修改系统设置权限。
- 不申请 `FOREGROUND_SERVICE` 以外的无关权限；若为兼容更高 Android 版本需要声明，也不改变 API 25 的实际运行基线。
- `MainActivity` 导出；`GatewayService` 和普通内部组件不导出；`BootReceiver` 只接收系统受保护广播。
- APK 不声明明文网络客户端，不内置 WebView 远程加载，不打开系统浏览器跳转外链。

## 4. 组件与线程模型

```text
MainActivity
  |  bindService / 本地配置
  v
GatewayService（前台服务）
  |-- RadioSession（单实例）
  |     |-- BluetoothLink（连接线程 + 接收线程）
  |     `-- CommandScheduler（单线程队列）
  |-- StatusRepository（不可变快照）
  |-- LocalWebServer（accept 线程 + 有界工作线程）
  |-- AuthManager（令牌、Cookie、限流）
  |-- SseHub（最多 4 个长连接）
  `-- AuditStore（SQLite，后台串行写）
```

线程规则：

1. `BluetoothSocket` 的输入和输出只能由 `BluetoothLink` 持有。
2. 所有 GAIA 请求只能进入 `CommandScheduler`，任何组件都不得绕过它直接调用写 Socket。
3. `StatusRepository` 使用 volatile 不可变快照，不做锁内网络 I/O。
4. HTTP 工作线程只读取快照和提交只读刷新请求，不等待蓝牙响应后阻塞页面。
5. SSE 推送从事件线程写入客户端队列；每个客户端写入有超时，慢客户端会被关闭。
6. Activity 只通过 Binder 调用服务，不直接持有 `BluetoothLink`。
7. 服务停止时按以下顺序关闭：停止接受网页请求 → 关闭 SSE → 取消调度队列 → 关闭蓝牙 → 保存审计。

## 5. GatewayService 生命周期

### 5.1 启动来源

- 用户在 Activity 点击“启动网关”。
- 用户配置了“开机保持运行”且已完成设备配对时，`BootReceiver` 拉起服务。
- ADB 调试启动只用于开发，不作为长期运行依赖。

### 5.2 启动顺序

```text
读取配置
→ 检查蓝牙适配器和定位权限
→ 创建前台通知
→ 申请部分 CPU 唤醒锁和高性能 Wi-Fi 锁
→ 启动 LocalWebServer（即使电台离线也可显示离线原因）
→ 启动 RadioSession
→ 连接选定 N7500
→ 注册通知并读取初始快照
→ 进入轮询与事件监听
```

启动顺序中不得发送任何写命令。即使将来加入写能力，服务启动也不得“恢复上次发射”或“恢复上次设置”。

### 5.3 停止来源

- 用户在 Activity 点击“停止网关”。
- 系统因权限或配置错误要求停止。
- 应用升级或用户卸载。

停止时必须关闭前台通知，不保留网络监听，不保留蓝牙 Socket。

## 6. 状态机

网关状态：

```text
STOPPED
STARTING
CONNECTING_BLUETOOTH
ONLINE
DEGRADED
RECONNECTING
FAULT
```

| 状态 | 条件 | 网页表现 |
| --- | --- | --- |
| `STOPPED` | 服务未运行 | 连接失败或显示“服务未启动” |
| `STARTING` | 正在读配置、启动 HTTP | 初始化中 |
| `CONNECTING_BLUETOOTH` | 已选设备，正在连接 | 黄色，保留旧快照但标过期 |
| `ONLINE` | 蓝牙正常且最近快照未过期 | 绿色 |
| `DEGRADED` | 蓝牙仍在，但读取失败或快照过期 | 橙色 |
| `RECONNECTING` | 蓝牙断开或连接失败，正在退避重试 | 黄色，持续显示原因 |
| `FAULT` | 权限、配置、存储等不可恢复错误 | 红色，要求本地处理 |

电台暂时断电、超出范围或蓝牙关闭应停留在 `RECONNECTING`，不能永久进入 `FAULT`，这样电台恢复后仍能自动重连。重连间隔为 `1, 2, 4, 8, 16, 30, 30...` 秒。

每次蓝牙会话重建：

- 生成新的 `sessionEpoch`。
- 取消旧队列中的请求。
- 拒绝旧会话迟到的响应。
- `StatusRepository` 保留最后已知值，但将 `connection.state` 改为 `RECONNECTING`，并把快照标为过期。

## 7. 只读命令调度

### 7.1 队列规则

- 单一工作线程按提交顺序发送，不允许两个 GAIA 请求同时在途。
- 每个请求有 `command`、`sessionEpoch`、`submittedAt`、`deadlineMs`。
- 同一命令已有请求等待时，新请求返回现有任务，不重复发送。
- 每轮快照最多读取一次同一命令。
- 默认响应超时 2000 ms，单条命令总预算 3000 ms。
- 超时后记一次失败，不无限重试；由下一轮轮询恢复。
- 连续三次快照读取失败，网关进入 `DEGRADED`。
- 蓝牙异常立即进入 `RECONNECTING`。

### 7.2 允许的请求入口

`CommandScheduler` 只暴露具名只读方法：

```java
void requestDeviceInfo();
void requestSettings();
void requestStatus();
void requestVolume();
void requestChannel(int channelId);
void requestNotificationRegistration();
```

不提供 `send(byte[])`、`sendRaw(byte[])`、`writeCommand(int, byte[])` 或等价通用入口。网页触发刷新只能调用这些方法。

### 7.3 轮询计划

| 数据 | 正常间隔 | 说明 |
| --- | ---: | --- |
| 电台状态 | 5 秒 | 收发、RSSI、当前信道、扫描 |
| 设置 | 30 秒 | A/B、静噪、扫描标志 |
| 音量 | 30 秒 | 0～15 |
| 当前信道记录 | 60 秒或当前信道变化时 | 名称与频率缓存 |
| 设备信息 | 连接后一次 | 重连后重新读取 |

收到 `HT_STATUS_CHANGED` 后，在 250 ms 内合并触发一次状态读取；如果已有状态读取在途，只标记一次待刷新。

## 8. 快照仓库

### 8.1 不可变快照

`StatusRepository` 保存一份不可变对象。每次有效更新构造新对象并原子替换，禁止网页直接访问成员会被并发修改的可变对象。

必填字段：

```text
schemaVersion = 1
instanceId      服务每次启动新生成，例如 gw-7f3c2a91
revision        同一实例内单调递增
generatedAt     本次 HTTP 响应生成时间，UTC ISO-8601
updatedAt       最后一次广播或通知更新时间，UTC ISO-8601；没有有效读取时为 null
staleAfterMs    默认 15000
stale           当前时间 - updatedAt > staleAfterMs，或 connection.state 非 CONNECTED
source          poll / notification / initial / none
```

示例：

    "productId": "0x0008",

规则：

- 未读取成功的字段必须是 `null`，不能用猜测值填充。
- 不返回蓝牙 MAC、局域网 IP、序列号、原始 GAIA 帧、令牌、Cookie 或完整日志。
- `revision` 可以在同值轮询时递增，以表达“刚成功刷新”；SSE 可做节流。
- 连接断开后不删除最后快照，但 `stale` 必须为 `true`，页面不得把它显示为实时值。
- 已有最后已知快照时，离线请求仍返回 `200`；只有从未成功读取且电台离线时才返回 `503 RADIO_OFFLINE`。
- 服务重启时生成新的 `instanceId`；客户端先比较实例再比较 revision。

## 9. HTTP 服务规则

### 9.1 实现方式

G1 使用 `ServerSocket` 和内置线程池，不引入 Netty、Jetty 或 WebView 服务器。HTTP/1.1，普通 JSON 页面使用 `Connection: close`，SSE 使用长连接。

限制：

- 请求行最大 2048 字节。
- Header 合计最大 8192 字节。
- `POST /api/v1/session` 请求体最大 1024 字节。
- 连接建立后 5 秒内必须收到完整请求头。
- 工作线程最多 4 个；SSE 客户端最多 4 个。
- 只处理精确注册的路径，不做目录遍历。
- 任何未知路径和不支持的方法返回 404 或 405，不返回栈信息。
- 所有响应带 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`。
- 页面响应带禁止外链脚本、禁止框架嵌套的 CSP。
- 不返回 `Access-Control-Allow-Origin`，默认不允许跨站脚本调用 API。
- 日志只记录 requestId、方法、路径、状态码和耗时，不记录 Cookie、Authorization 或表单原文。

### 9.2 路由表

| 方法 | 路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| GET | `/healthz` | 否 | 最小健康信息 |
| GET | `/login` | 否 | 内置登录页 |
| POST | `/api/v1/session` | 令牌表单 | 建立会话 Cookie |
| DELETE | `/api/v1/session` | Cookie | 退出登录 |
| GET | `/` | Cookie | 只读状态页 |
| GET | `/assets/app.js` | 否 | 内置静态脚本 |
| GET | `/assets/style.css` | 否 | 内置样式 |
| GET | `/api/v1/snapshot` | Bearer 或 Cookie | 完整只读快照 |
| GET | `/api/v1/events` | Bearer 或 Cookie | SSE 事件流 |

不注册 `POST /ptt`、`POST /volume`、`POST /scan`、`POST /channel`、`PUT /settings`、`POST /firmware` 等路径。命中时返回 404。

### 9.3 登录流程

1. 浏览器访问 `/`，无有效 Cookie 时 303 到 `/login`。
2. 用户在登录页输入访问令牌，提交到 `/api/v1/session`。
3. 服务端只校验令牌哈希，成功后生成随机会话并设置 Cookie。
4. 登录成功 303 到 `/`；失败返回登录页并显示错误码。
5. 连续 5 次失败后，同一来源 60 秒内直接返回 429。
6. Cookie 默认 12 小时过期；服务重启或用户退出可立即失效。

## 10. 令牌与会话

### 10.1 访问令牌

- 首次创建时使用 `SecureRandom` 生成 32 字节随机值，Base64 URL-safe 无填充。
- 对外显示格式为 `n75_<随机串>`。
- SharedPreferences 只保存 SHA-256 哈希和创建时间，不保存原文。
- N1 本地界面可以临时显示新令牌一次，关闭页面后只能重新生成。
- 令牌轮换后，所有旧会话和旧 Bearer 令牌立即失效。
- 比较哈希时使用 `MessageDigest.isEqual`，不能使用普通字符串提前返回。
- 令牌不得进入 URL、日志、审计详情或网页 DOM 的持久存储。

### 10.2 会话 Cookie

```text
名称：n75_session
属性：HttpOnly; SameSite=Strict; Path=/; Max-Age=43200
Secure：G1 无 HTTPS，因此不设置；只允许回环或 Tailscale 链路使用
```

- 会话值同样为 32 字节随机数，服务端只保存哈希、过期时间和创建来源哈希。
- 会话最多 8 个，超出时淘汰最旧会话。
- Cookie 不包含权限角色、设备信息或明文令牌。
- G1 唯一角色是 `observer`，没有管理员写权限。
- CORS 默认关闭，不设置通配来源。

### 10.3 Bearer 访问

- `Authorization: Bearer n75_...` 适用于 `/api/v1/snapshot` 和 `/api/v1/events`。
- Bearer 令牌不写入服务器访问日志。
- 401 响应必须带 `WWW-Authenticate: Bearer`。
- 认证失败按来源限流，不向客户端区分“令牌不存在”和“哈希不正确”的细节。

## 11. SSE 事件流

事件格式：

```text
event: ready
id: gw-7f3c2a91:42
data: {"instanceId":"gw-7f3c2a91","revision":42}

event: snapshot
id: gw-7f3c2a91:43
data: {"instanceId":"gw-7f3c2a91","revision":43,"updatedAt":"2026-11-27T14:25:03Z","stale":false}

event: heartbeat
data: {"at":"2026-11-27T14:25:18Z"}
```

规则：

- 每个新连接先发 `ready`。
- 状态更新发送 `snapshot` 摘要，不发送完整快照，客户端收到后拉取 `/snapshot`。
- 每 15 秒发送一次 `heartbeat`。
- 客户端断开、写超时或实例重启时关闭连接。
- 页面失焦后关闭 EventSource；重新聚焦时先拉快照再重连。
- SSE 不发送令牌、设备地址、原始帧或完整审计记录。

## 12. 网络绑定

### 12.1 三种模式

| 模式 | 默认 | 监听地址 | 使用条件 |
| --- | --- | --- | --- |
| `LOOPBACK` | 是 | `127.0.0.1:8710` | 本机调试，最安全 |
| `WIFI` | 手动 | 选定的一个局域网 IPv4:8710 | 必须已有令牌，本地确认风险 |
| `TAILSCALE` | 手动 | 选定的 Tailscale IPv4:8710 | 必须已有令牌，本地确认风险 |

不绑定 `0.0.0.0`，不提供多接口同时监听，不提供公网端口映射开关。外部模式每次修改都要在 N1 本地确认。只有用户额外勾选“开机后保持外部模式”时，开机重启才恢复上次外部绑定。

### 12.2 地址选择

- `WIFI`：枚举非回环 IPv4 地址，由用户明确选择；页面只显示该地址最后 8 位或标签，不记录完整地址到公开日志。
- `TAILSCALE`：枚举 VPN 或 `tun` 类接口，并要求用户确认期望地址；不能仅凭接口名自动开放。
- 绑定失败时停留在本地错误状态，不退回 `0.0.0.0`。
- Wi-Fi 地址变化时停止旧监听、重新绑定，并通知网页重连。

### 12.3 传输安全

- `LOOPBACK` 可使用 HTTP。
- `TAILSCALE` 可使用 HTTP，因为链路由 Tailscale 隧道加密；页面仍显示“依赖 Tailscale”。
- `WIFI` 使用 HTTP 时页面持续显示“局域网明文访问”，仅限可信家庭网络。
- G1 不启用 HTTPS；进入任何远程写入阶段前必须重新评审，并优先改为 Tailscale-only 或 HTTPS。

## 13. 本地 Activity 界面

主界面分四块：

1. 设备与网关状态：蓝牙适配器、已选设备、连接状态、前台服务状态。
2. 电台选择与启动：已配对设备下拉框、连接后启动、停止网关。
3. 访问控制：绑定模式、监听地址、令牌创建/轮换、一次性显示令牌、会话撤销。
4. 诊断摘要：快照 revision、最后更新时间、重连次数、最近错误码、打开日志按钮。

界面约束：

- 横屏显示，主要按钮不被裁切。
- 所有权限拒绝、蓝牙关闭、未配对和绑定失败都要显示可操作的中文原因。
- 不在主界面显示完整蓝牙 MAC；只显示设备名称和短标签。
- 不在日志中打印令牌或完整 Cookie。
- 停止服务前取消所有轮询，不留下前台通知或监听 Socket。
- 配置项写入 SharedPreferences，包含：设备短标识、自动启动、允许外部模式开机恢复、绑定模式、端口。真实设备地址只保存在本地私有配置中。

## 14. 网页界面

### 14.1 状态页

顶部固定栏：

```text
N1Gateway | ONLINE / RECONNECTING / STALE | instanceId:revision
```

主体卡片：

- 电台电源、发射、接收、RSSI。
- 当前信道、A/B、扫描、音量。
- 设备产品 ID、软件版本、信道数、区域数。
- 最后更新时间、数据新鲜度、最近错误。
- 连接和鉴权审计摘要。

底部：刷新按钮、SSE 状态和“最后成功刷新时间”。不显示 PTT、音量滑块、扫描开关、信道选择或任何写按钮。

### 14.2 前端实现

- 纯 HTML/CSS/JavaScript，不使用 CDN、第三方统计、远程字体或外链图片。
- 使用 `EventSource` 从 `/api/v1/events` 接收摘要；心跳缺失超过 45 秒时显示断线。
- 每次 `snapshot` 事件最多每 1 秒触发一次 `/api/v1/snapshot` 拉取，避免事件风暴。
- 收到 `instanceId` 变化时丢弃旧快照并重新加载页面状态。
- `fetch` 请求设置 `cache: no-store`，不把令牌放进查询串。
- 页面失焦时停止 SSE，恢复时重新拉快照。
- 不把令牌或设备状态写入 `localStorage`。

## 15. 审计与日志

审计表字段：

```text
id, occurredAtUtc, category, severity, code, message,
sourceTag, instanceId, sessionHashPrefix
```

规则：

- `message` 只保存脱敏摘要，不保存令牌、Cookie、完整 IP、完整 MAC、原始 GAIA 帧。
- `sourceTag` 是服务端随机盐的哈希前缀，仅用于关联同一来源的失败事件。
- 保留 30 天或最多 5000 条，以先到者为准。
- 审计写入失败不能阻塞蓝牙轮询；记录到本地滚动日志并继续运行。
- 原始蓝牙收发日志只保存在 N1 私有目录，最多 3 个文件，每个 1 MiB，不通过网页下载。
- `/healthz` 和 `/snapshot` 不返回审计原文。

## 16. 错误码

| 错误码 | HTTP | 场景 |
| --- | ---: | --- |
| `AUTH_REQUIRED` | 401 | 无 Cookie 或 Bearer |
| `AUTH_FAILED` | 401 | 令牌或会话错误 |
| `SESSION_EXPIRED` | 401 | 会话过期 |
| `RATE_LIMITED` | 429 | 连续鉴权失败 |
| `RADIO_OFFLINE` | 503 | 快照请求时电台离线 |
| `METHOD_NOT_ALLOWED` | 405 | 路径存在但方法不支持 |
| `NOT_FOUND` | 404 | 未知路径或写接口 |
| `PAYLOAD_TOO_LARGE` | 413 | 请求体或 Header 超限 |
| `TOO_MANY_CLIENTS` | 429 | SSE 客户端超过上限 |
| `INTERNAL_ERROR` | 500 | 未分类错误，不返回堆栈 |

统一错误 JSON：

```json
{
  "ok": false,
  "code": "AUTH_FAILED",
  "message": "访问令牌不正确",
  "requestId": "req-7a18c2"
}
```

`requestId` 只用于本地排查，不包含设备地址或令牌。`message` 是固定中文提示，不拼接异常原文。

## 17. 测试设计

### 17.1 JVM 离线自测

至少覆盖：

1. GAIA 帧编码、响应解析和半包/粘包处理。
2. 只读命令白名单；未知命令被拒绝。
3. 同命令在途合并，不产生重复蓝牙请求。
4. 会话 epoch 变化后拒绝旧响应。
5. 快照 revision 单调递增和 stale 计算。
6. JSON 字符串转义、null 字段和 UTF-8 输出。
7. 令牌哈希、恒定时间比较、过期和轮换。
8. 5 次失败限流与 60 秒恢复（使用假时钟）。
9. HTTP 请求行/Header/表单长度限制。
10. 未知写路径返回 404，不支持方法返回 405。
11. SSE ready/snapshot/heartbeat 格式。
12. 审计消息不含令牌、完整 IP 和完整 MAC。

### 17.2 N1 实机验收

- G1-A：前台服务启动，屏幕保持常亮并连续在线；2 小时长稳待复测。
- G1-B：`127.0.0.1:8710/api/v1/snapshot` 返回完整快照。
- G1-C：无令牌返回 401，错误令牌触发限流，登录后 Cookie 可读取。
- G1-D：电脑和 iPhone 各开一个页面，revision 同步；状态变化 2 秒内显示。
- G1-E：N7500 断电 3 次，恢复后自动重连；N1 重启后按配置恢复。
- G1-F：屏幕常亮连续运行 2 小时，内存无持续增长；30 分钟轮询无解析异常。若手动关屏导致整机休眠断网，不计为通过。
- G1-G：抓包和日志中不存在 `SET_VOLUME`、`WRITE_SETTINGS`、PTT、音频或固件字节。

### 17.3 失败即停止条件

出现以下任一情况时，停止测试并保留现场日志：

- 网页线程能触发未知写命令。
- 蓝牙断开后持续显示旧快照为实时。
- 无令牌可读取设备详情。
- 令牌或 Cookie 出现在日志、URL 或 SSE data 中。
- 服务启动时自动进入外部绑定而未获得本地确认。
- 出现任何 PTT 或音频发送字节。

## 18. 实施顺序

1. 新建工程并复制协议代码，保持第二阶段可独立运行。
2. 完成 `GatewayState`、`GatewayConfig`、`StatusRepository` 和 JVM 自测。
3. 完成 `RadioSession`、`CommandScheduler` 和初始只读快照。
4. 完成前台服务、通知和 Activity 启停。
5. 完成回环 HTTP、健康检查和快照 JSON。
6. 完成令牌、登录页、Cookie 和限流。
7. 完成 SSE、电脑页面和手机页面。
8. 完成 Wi-Fi/Tailscale 手动绑定和开机恢复。
9. 在真实 N1 和 N7500 上执行 G1-A 到 G1-G。
10. 只有 G1 全部通过后，才评审 G2 的低风险写入。

## 19. 设计结论

G1 的成功标准不是“网页能看一次状态”，而是：服务长时间在线、蓝牙可重连、页面能识别过期、令牌能保护详情、两个客户端看到同一 revision，并且代码与网络流量中完全不存在写命令、PTT 或音频路径。

在 G1 完成前，不进入远程音量、扫描、信道写入，更不进入远程 PTT。
