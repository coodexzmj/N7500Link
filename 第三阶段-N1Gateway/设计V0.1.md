## 1. 本阶段结论

第三阶段不直接复制安卓 HT 的聊天室，也不先做远程 PTT，而是把 N1 变成稳定的“电台网关”：

```text
电脑浏览器 / iPhone Safari
          |
   家庭 Wi-Fi 或 Tailscale
          |
   N1 常驻前台服务
          |
   Bluetooth Classic / RFCOMM
          |
     WENNUO N7500
```

第一版只提供**远程只读监控**：查看电台是否在线、当前收发状态、当前信道、音量和最近事件。电脑和手机不能修改电台设置，也不能发射。

这样安排的原因：

1. 当前实机已经验证蓝牙连接和只读状态读取。
2. 音量和扫描写入的 50 次稳定性验收尚未完成。
3. 音频与 PTT 还缺少断线释放、超时释放和本地急停的实机验证。
4. 先把网络层、权限层和状态层做稳，后续添加写入时才不会把风险带进发射链路。

## 3. 第三阶段范围

### 3.1 本期实现

- N1 前台服务常驻，不依赖 USB 或 ADB 在线。
- 服务独占蓝牙连接，界面只负责配对、启动和本地授权。
- 电脑和 iPhone 通过浏览器查看同一份电台快照。
- 服务端主动推送状态变化，页面断线后自动重连。
- 访问令牌、只读角色和失败审计。
- N7500 或蓝牙断开时显示明确的离线原因。
- N1 默认保持屏幕常亮；Wi-Fi 短暂中断后可自动恢复。熄屏深度休眠不作为当前固件下的可用运行模式。
- N1 重启后可自动拉起服务，但不会自动发射。

### 3.2 本期明确不做

- 远程修改音量、扫描或信道。
- 远程写入信道记录、频率、亚音、功率或带宽。
- 远程 PTT。
- 音频接收、播放、上传或录音。
- HT 账号、聊天室、成员管理或官方服务器。
- 固件升级、工厂复位和任何不可逆操作。
- 公网端口映射。

## 4. 服务拆分

建议将现有 `MainActivity` 中的蓝牙逻辑迁移到以下组件：

```text
┌──────────────────────────────────────────────┐
│ N1Control Activity                           │
│ 配对设备 / 选择设备 / 显示令牌 / 启动服务    │
└───────────────────┬──────────────────────────┘
                    │ Binder 命令
┌───────────────────▼──────────────────────────┐
│ GatewayService（前台服务）                   │
│  连接监督 / 通知 / 开机启动 / 本地急停状态   │
└───────────────┬──────────────────┬───────────┘
                │                  │
┌───────────────▼──────────┐  ┌────▼──────────────┐
│ RadioSession             │  │ LocalWebServer     │
│ RFCOMM / GAIA / 解析     │  │ HTTP / SSE / 鉴权  │
└───────────────┬──────────┘  └────┬──────────────┘
                │                  │
┌───────────────▼──────────┐  ┌────▼──────────────┐
│ CommandScheduler         │  │ StatusRepository   │
│ 单队列 / 单写锁 / 白名单 │  │ revision / 快照缓存│
└──────────────────────────┘  └───────────────────┘
```

组件职责：

| 组件 | 职责 |
| --- | --- |
| `GatewayService` | 前台服务、生命周期、通知、开机恢复、整体监督 |
| `RadioSession` | 蓝牙选择、RFCOMM 连接、GAIA 收发包、断线检测 |
| `CommandScheduler` | 串行发送只读命令，禁止并发和命令插队 |
| `StatusRepository` | 维护最新快照和 revision，向界面与网页提供只读数据 |
| `LocalWebServer` | 提供页面、JSON API、SSE 事件流和令牌校验 |
| `AuditStore` | 记录连接、鉴权失败、离线、恢复和配置变化 |
| `AuthManager` | 生成、校验、撤销和轮换访问令牌，管理 Cookie 与限流 |

关键原则：除 `RadioSession` 外，任何界面、网页或后台线程都不能直接读写蓝牙 Socket。

## 5. 状态与并发模型

### 5.1 网关状态

```text
STOPPED
  -> STARTING
  -> CONNECTING_BLUETOOTH
  -> ONLINE
  -> DEGRADED
  -> RECONNECTING
  -> FAULT
```

- `ONLINE`：蓝牙连接正常，最近一次快照未超时。
- `DEGRADED`：连接仍在，但连续读取失败或状态超过阈值未更新。
- `RECONNECTING`：蓝牙断开，正在按退避策略重连。
- `FAULT`：权限、配置或不可恢复错误，需要本地处理。

本期无发射状态，因此网关状态不包含 `TX`。

### 5.2 快照规则

快照必须带：

- `schemaVersion`：固定为 `1`。
- `instanceId`：服务每次启动生成的新实例标识，避免重启后的 revision 被误认为同一序列。
- `revision`：同一实例内每次有效更新递增。
- `generatedAt`：本次 HTTP 响应生成时间。
- `updatedAt`：最后一次成功读取时间；从未成功读取时为 `null`。
- `staleAfterMs`：超过此时间标记为过期。
- `source`：`none`、`initial`、`poll` 或 `notification`。
- `gateway`：网关状态、版本、启动时间和最近错误码。
- `connection`：蓝牙连接状态、短设备标签、连接时间和最近错误。
- `radio`：电台设备信息、设置与状态。
- `volume`：已读取音量；未读取时为 `null`。
- `channel`：当前信道记录；未知时为 `null`。

字段枚举和必填项以 [HTTP API V1 合同](API-V1.yaml) 为精确依据。`gateway.state` 使用 `STOPPED`、`STARTING`、`CONNECTING_BLUETOOTH`、`ONLINE`、`DEGRADED`、`RECONNECTING`、`FAULT`；`connection.state` 使用 `DISCONNECTED`、`CONNECTING`、`CONNECTED`、`RECONNECTING`、`FAULT`。

网页只能显示缓存快照，不能把“最后已知值”冒充实时值。状态过期时必须显示黄色或红色提示。

### 5.3 发送队列

- 同一时间只允许一个 GAIA 请求在途。
- UI 刷新、网页订阅和定时轮询统一进入只读队列。
- 重复读取在 1 秒内合并，避免多客户端放大蓝牙请求。
- 连接重建时清空旧队列并提升 revision，防止旧响应写入新会话。
- 本期不开放写命令，因此不考虑写回滚；接口仍应为后续写锁预留字段。

## 6. 网络接口

第一版采用 HTTP/1.1 + JSON + Server-Sent Events，先不引入 WebSocket。原因是只读监控不需要双向低延迟控制，SSE 足够，调试和兼容成本更低。远程写入和音频阶段再升级到 WebSocket。

统一前缀：`/api/v1`

### 6.1 健康检查

```http
GET /healthz
```

不需要令牌，只返回最小信息：

```json
{"ok":true,"service":"n7500link-gateway","version":"0.3.8"}
```

不得返回电台地址、令牌、日志或设备序列号。

### 6.2 登录与令牌

浏览器首次访问显示令牌输入页。服务端校验成功后设置 HttpOnly、SameSite=Strict 的会话 Cookie。

浏览器登录接口：

```http
GET  /login
POST /api/v1/session
DELETE /api/v1/session
```

- `POST /api/v1/session` 只接受表单字段 `token`，校验成功后设置会话 Cookie 并跳转到首页。
- `DELETE /api/v1/session` 清空会话 Cookie；不接受令牌通过 URL 传递。
- `/login` 是内置静态页面，不从 CDN 加载脚本或样式。

API 也允许：

```http
Authorization: Bearer <token>
```

规则：

- 令牌由服务端使用 `SecureRandom` 生成 10 位大写字母与数字，排除易混淆字符；约 50 位随机强度，只适用于回环、局域网或 Tailscale 链路，不用于公网直连。
- 本地只保存令牌哈希，不保存令牌原文。
- 令牌只在 N1 本地页面显示，用户确认后可以隐藏。
- 令牌不得出现在 URL 查询串。
- 连续 5 次鉴权失败后，对该来源暂停 60 秒。
- 本期只有 `observer` 角色；未来写入角色单独增加。

### 6.4 事件流

```http
GET /api/v1/events
Authorization: Bearer <token> 或登录 Cookie
Accept: text/event-stream
```

事件类型：

- `ready`：连接建立后立即发送一次，携带 `instanceId` 和当前 `revision`。
- `snapshot`：快照 revision 变化时发送摘要，携带 `instanceId`、`revision`、`updatedAt` 和 `stale`。
- `heartbeat`：每 15 秒发送一次，携带 `at` 时间。

事件不发送完整快照、审计原文、设备地址或令牌；客户端收到 `snapshot` 后重新拉取 `/api/v1/snapshot`。

### 6.5 错误格式

```json
{
  "ok": false,
  "code": "AUTH_REQUIRED",
  "message": "需要访问令牌",
  "requestId": "req-..."
}
```

建议错误码：

| 错误码 | HTTP 状态 | 含义 |
| --- | ---: | --- |
| `AUTH_REQUIRED` | 401 | 没有 Cookie 或 Bearer |
| `AUTH_FAILED` | 401 | 令牌或会话错误 |
| `SESSION_EXPIRED` | 401 | 会话过期 |
| `RATE_LIMITED` | 429 | 连续鉴权失败或客户端过多 |
| `RADIO_OFFLINE` | 503 | 从未成功读取过快照且电台离线 |
| `METHOD_NOT_ALLOWED` | 405 | 路径存在但方法不支持 |
| `NOT_FOUND` | 404 | 路径不存在或命中未开放的写接口 |
| `PAYLOAD_TOO_LARGE` | 413 | 请求体或 Header 超限 |
| `TOO_MANY_CLIENTS` | 429 | SSE 客户端超过上限 |
| `INTERNAL_ERROR` | 500 | 服务端错误，不返回堆栈 |

### 6.6 本期不存在的接口

本期不得注册以下方法：

- `POST /ptt`
- `POST /volume`
- `POST /scan`
- `POST /channel`
- `PUT /settings`
- `POST /firmware`

即使请求命中这些路径，也必须返回 `404`，避免后续误把预留接口当成已实现能力。

## 7. 网络绑定与安全

### 7.1 绑定模式

| 模式 | 默认 | 用途 |
| --- | --- | --- |
| 回环模式 | 是 | 仅 `127.0.0.1`，用于本机调试 |
| Tailscale 模式 | 手动开启 | 只监听 Tailscale 接口地址 |
| 局域网模式 | 手动开启 | 仅可信家庭 Wi-Fi，界面需持续提示风险 |

默认不监听 `0.0.0.0`，不允许通过路由器端口映射访问。

### 7.2 传输层

第一期优先在 Tailscale 内使用 HTTP，借助 Tailscale 自带加密隧道；可信家庭局域网可临时使用 HTTP，但必须在页面上明确标识。

进入远程写入阶段前必须完成以下之一：

1. 启用 HTTPS 并配置受信任证书；或
2. 明确冻结为“只允许 Tailscale 访问”，并把 HTTP 明文限制为回环地址。

### 7.3 账号边界

- 不使用 HT 账号充当网关账号。
- 不保存 HT 频道口令、聊天室信息或官方 token。
- N1 本地令牌与 Tailscale 身份相互独立。
- 撤销令牌不影响 Tailscale 账号。
- 远程维护者也不能触发 APK 安装或固件升级。

## 8. 界面设计

### 8.1 电脑页面

第一屏显示：

- 网关在线 / 离线
- 蓝牙在线 / 重连中
- 电台电源、发射、接收、RSSI

### 8.2 iPhone 页面

## 9. 后台运行与开机恢复

- 使用前台服务并显示常驻通知“N7500Link 网关：在线/重连中”。
- `BOOT_COMPLETED` 后只在已配置设备时启动服务。
- 服务启动后先执行安全状态检查，再连接蓝牙；本期不发送 PTT 相关字节。
- Wi-Fi 断线时保持蓝牙电台连接，网页客户端自行重连。
- 0.3.5 默认开启屏幕常亮，并在服务运行期间持有屏幕唤醒锁、部分 CPU 唤醒锁和高性能 Wi-Fi 锁。0.3.3 实测表明该 N1 固件熄屏后仍会整机休眠并断开 Wi-Fi，因此不能只依赖 CPU/Wi-Fi 锁。0.3.5 延后界面开关监听绑定，避免初始化误写，并用独立迁移键纠正 0.3.4 的持久化错误。停止服务时三类锁成对释放；屏幕锁也不等于允许无线发射。
- 蓝牙离线时保持 `RECONNECTING`，按退避策略持续重试；`FAULT` 只用于权限、配置、存储等不可恢复错误。
- 服务进程被杀后不允许自动执行任何“恢复上次发射”动作；本期也没有发射能力。

## 10. 数据与审计

第一期需要保存：

| 数据 | 存储 | 保留 |
| --- | --- | --- |
| 令牌哈希 | 私有配置 | 直到撤销或重置 |
| 设备配对选择 | 私有配置 | 长期 |
| 监听模式 | 私有配置 | 长期 |
| 服务状态事件 | SQLite | 30 天 |
| 鉴权失败 | SQLite | 30 天 |
| 连接与解析错误 | 日志/SQLite | 7～30 天 |
| 电台快照 | 内存 | 重启后重新读取 |
| 原始音频 | 不保存 | 不适用 |

审计字段不得包含令牌原文、HT 账号、频道口令或完整蓝牙 MAC。

### 11.2 G1 稳定性验收

- 连续只读轮询 30 分钟，无半包/粘包导致的错误解析。

第三阶段使用独立包名 `com.bi4byf.n7500link.gateway`，与第二阶段 `com.bi4byf.n7500link.control` 分开安装。

实现顺序建议：

1. 保留现有 `N1Control` 作为验证工具，不直接破坏它。
2. 新建 `第三阶段-N1Gateway` 工程，复制已验证的协议代码。
3. 先做前台服务和蓝牙会话，不开放网络。
4. 再增加本机 `127.0.0.1` HTTP 快照。
5. 最后增加令牌、Tailscale/局域网绑定和 SSE。

## 14. 后续写入阶段的门槛

第三阶段只读监控通过后，才考虑远程低风险写入。进入 G2 前必须满足：

- 第二阶段音量和扫描写入完成 50 次稳定性验收。
- A/B 切换回读与恢复验证通过。
- 所有写命令具备原值、目标值、回读值和回滚结果。
- 实现单操作员锁、请求幂等和状态 revision 校验。
- 页面写操作必须二次确认。
- 任何远程写入都必须可在 N1 本地停用。

远程 PTT 仍必须等待本地音频与 PTT 安全阶段通过，不能把 G1 或 G2 直接扩展成远程发射。

## 15. 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| N1 厂商固件限制后台 | 服务被系统清理 | 前台服务、开机自启、2 小时实测 |
| Wi-Fi 省电策略 | 熄屏后网页和 ADB 网络掉线 | 服务运行期间持有高性能 Wi-Fi Lock；首次实机试运行发现旧包无锁会掉线，已修正并重新验收 |
| 蓝牙与音频争用 | 后续无法同时收发 | 控制通道与音频通道分阶段验证 |
| 明文 HTTP | 令牌或状态泄露 | 默认回环、优先 Tailscale、写阶段前启用 HTTPS |
| 多客户端轮询放大 | 蓝牙队列拥塞 | 快照缓存、合并读取、SSE 推送 |
| 旧版本页面缓存 | 显示过期状态 | revision、updatedAt、stale 标志 |
| Android 7.1 浏览器兼容 | iPhone/PC 页面行为不一致 | 使用基础 HTML/JS、Safari 实测 |

## 16. 设计结论

第三阶段的正确起点不是“远程 PTT”，而是让 N1 成为可长期运行、可鉴权、只读且可观测的电台网关。

第一版只做远程监控，能够把当前已经实机验证的蓝牙读取能力稳定地提供给电脑和 iPhone，同时保持 PTT、音频和设置写入完全关闭。完成 G1 验收后，再根据真实运行数据决定是否进入远程低风险写入和音频阶段。
