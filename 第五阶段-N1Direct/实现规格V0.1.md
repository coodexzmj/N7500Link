## 2. 固定架构

```text
Windows 浏览器 / iPhone Safari
              |
      家庭 Wi-Fi / Tailscale
              |
          N1Direct 0.6.0
              |
 Bluetooth Classic / RFCOMM / GAIA
              |
        WENNUO N7500
```

```text
MainActivity                 配对、令牌、日志、启停与五页原生界面
GatewayService               前台服务、开机恢复、屏幕/CPU/Wi-Fi 锁
GatewayBootScheduler         开机任务调度
BootReceiver                 启动广播
RadioSession                 唯一蓝牙连接、链路 epoch、状态轮询
CommandScheduler             串行请求、读取来源标记与写命令白名单
BluetoothLink                RFCOMM Socket 与接收线程
GaiaCodec                    GAIA 帧编解码与命令边界
RadioParser                  设备、状态、音量、当前信道与目录信道解析
SettingsBlock                完整设置块复制与局部位修改
StatusRepository             不可变快照、revision、stale
LowRiskWriteController       单操作状态机、回读与最多一次回滚
ChannelCatalogService        固定 0..31 信道目录只读状态机
LocalWebServer               HTTP 路由、鉴权、JSON 与 SSE
AuthManager                  令牌哈希、Cookie、会话与失败限流
SseHub                       SSE 客户端管理和心跳
```

硬性规则：

1. 只有 `BluetoothLink` 可以持有和读写 `BluetoothSocket`。
2. HTTP 线程不能直接构造或发送 GAIA 帧。
3. 所有蓝牙请求必须进入 `RadioSession` / `CommandScheduler`。
4. 写请求必须经过 `LowRiskWriteController`，并只能命中 `GaiaCodec.isAllowedWriteCommand()` 白名单。
5. 当前信道读取和目录信道读取使用不同 `ReadSource`，目录响应还必须同时匹配请求 ID、目标信道号和链路 epoch。
6. 同一时间最多一个控制操作；目录读取遇到控制操作时延迟 250 ms 后继续排队。
7. 链路 epoch 改变时，目录数据、代次和在途请求全部清空，旧响应不得回填新链路。
8. 网页只使用随 APK 打包的本地 HTML/CSS/JavaScript，不加载 CDN、远程字体、统计脚本或 HT 云端资源。

## 4. 受限控制规格

### 4.1 GAIA 白名单

读取命令：

```text
GET_DEV_INFO(4)
REGISTER_NOTIFICATION(6)
READ_SETTINGS(10)
READ_RF_CH(13)
GET_HT_STATUS(20)
GET_VOLUME(22)
```

写入命令只有：

```text
WRITE_SETTINGS(11)
SET_VOLUME(23)
```

不允许从网页提交原始帧、任意命令号、任意设置块或频率字段。

### 4.2 音量、扫描与 A/B

- 音量范围固定 `0..15`；写入后延迟 900 ms 回读 `GET_VOLUME`。
- 扫描只切换 `SettingsBlock` 完整载荷中的扫描位。
- A/B 只切换完整载荷中的当前侧位，接口值只接受 `A` 或 `B`。
- 扫描和 A/B 回读必须对完整设置块逐字节比较，不能只比较目标位。
- 基线不足、响应状态不为 0、载荷不足 10 字节或命令不匹配时禁止写入。
- 写入只发送一次，不自动重试；回读不一致时最多回滚一次。
- 操作总超时 12000 ms，回滚超时 8000 ms，控制并发数为 1。
- 0.6.0 未扩大写白名单，也未新增信道设置写入。

控制状态：

```text
ACCEPTED -> BASELINE_READ -> WRITING -> READBACK -> READBACK_OK
```

失败路径包括 `TIMEOUT`、`UNAVAILABLE`、`READBACK_MISMATCH`、`ROLLBACK_WRITING`、`ROLLBACK_OK`、`ROLLBACK_FAILED`、`LINK_LOST`、`CANCELLED` 和 `CONTROL_BUSY`。

## 5. 信道目录实现

### 5.1 数据范围

目录固定为 32 项，信道编号只能为 `0..31`。每项包含：

```text
id
name
rxMHz
txMHz
status
stale
readAtMs
attemptedAtMs
errorCode
```

目录汇总包含：

```text
state
epoch
generation
total
completedCount
successCount
stale
lastRefreshAtMs
lastErrorCode
observedAtMs
channels
```

该能力只读取现有信道记录，不提供名称、频率、亚音、带宽、功率或分配编号的写入入口。

### 5.2 汇总状态机

| 状态 | 含义 |
| --- | --- |
| `EMPTY` | 当前链路 epoch 尚未开始读取 |
| `REFRESHING` | 正在逐信道串行读取 |
| `COMPLETE` | 本轮 32 项全部成功确认 |
| `PARTIAL` | 本轮结束，但至少一项超时或报错 |
| `OFFLINE` | 目录与电台当前链路不匹配，或电台不可用 |

单信道状态：

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 本轮尚未完成 |
| `OK` | 已成功解析该信道 |
| `TIMEOUT` | 等待响应超时 |
| `ERROR` | 解析失败、响应过期、ID 错配或频率非法 |

`OK` 且 `name/rxMHz/txMHz` 为 `null` 表示已成功确认的空信道；`TIMEOUT/ERROR` 永远不能显示成空信道。

### 5.3 刷新与并发

- 首次已鉴权的 `GET /api/v1/channels` 请求在当前 epoch 内最多触发一次自动刷新。
- `POST /api/v1/channels/refresh` 启动新代次；同一代次正在刷新时重复请求是幂等的。
- 每代次最多只有一个目录读取在途，按 0 到 31 串行推进。
- 控制写入繁忙时，目录泵每 250 ms 重试排队，不抢占写入。
- 链路 epoch 改变会调用 `beginEpoch()` 清空全部目录值和状态。
- 刷新开始会将未完成的项重置为 `PENDING`，已有成功值只保留为过期候选。

### 5.4 响应匹配与值处理

目录结果只在以下全部匹配时接受：

```text
ReadSource == CATALOG
epoch == 当前目录 epoch
requestId == 在途请求 ID
targetChannelId == 在途信道号
```

- 超时、解析失败和过期响应保留上一次成功值，并设置 `stale=true`、`errorCode`。
- 无旧值时字段保持 `null`，不得用 0 MHz 占位。
- 解析出的信道 ID 与请求信道号不一致时记为 `CHANNEL_ID_MISMATCH`。
- 收发频率为 `0/0` 时转换为成功空信道 `null/null`。
- 任一频率为 0、负值或超过 1 GHz 时记为 `CHANNEL_FREQUENCY_INVALID`。
- 只有 `COMPLETE` 会清空 `lastErrorCode`；`PARTIAL` 保留最后一次失败原因。

## 6. HTTP 接口

```text
GET  /api/v1/channels
GET  /api/v1/channels/{id}
POST /api/v1/channels/refresh
```

| 情况 | 行为 |
| --- | --- |
| 列表请求且电台就绪 | 200；首次请求最多触发一次自动刷新，`EMPTY/REFRESHING` 也正常返回 |
| 单信道请求 | 200；只读取缓存，不临时触发蓝牙读取 |
| 刷新请求 | 202；`state=REFRESHING`，返回 `refreshEpoch` |
| 重复刷新请求 | 当前代次运行中仍返回 202，幂等 |
| 电台未连接 | 503 `RADIO_NOT_READY` |
| 刷新无法启动 | 503 `CATALOG_REFRESH_FAILED` |
| 编号为负、越界或整数溢出 | 400 `CHANNEL_OUT_OF_RANGE` |
| 末尾路径不是纯 ASCII 数字 | 404 `NOT_FOUND` |
| 方法不匹配 | 405 |

鉴权、请求体上限、`confirm:true`、控制互斥和写白名单继续沿用 0.5.0/0.4.0 规格，不因目录接口而变化。

## 7. 网页与原生界面

### 7.1 网页

页签为总览、直连控制、设备信息、当前信道、信道目录、网关状态、诊断和关于。信道目录页支持：

- 固定 32 行编号、名称、收发 MHz 和单信道状态。
- 按编号、名称、频率、状态和错误码搜索。
- 刷新进行中每 900 ms 轮询目录。
- 手动刷新按钮防重复提交。
- A/B 与当前信道标识。
- `stale` 过期标记、错误码、读取时间和尝试时间。
- 电台离线时显示接口错误，而不是伪造空信道。

### 7.2 原生界面

原生界面继续使用 0.5.0 已实机验证的微信风格“单屏 + 固定左侧菜单”，五页为运行状态、蓝牙电台、网络设置、运行选项、网关与令牌。`0.6.0` 只更新页脚版本，没有恢复上下滚动或把 32 行目录塞进原生页面。

## 12. 结论

0.6.0 完成了固定 `0..31` 信道目录的代码、离线门禁、APK 构建和真实 N1 安装验证；目录读取仍然只读，控制写白名单没有扩大。由于测试时 N7500 离线，真实 32 项信道实值、搜索和手动刷新仍需一次短复测。该版本不是完整 HT 替代版本，下一项信道分配切换属于新的设置写入，必须在用户明确批准后另行设计、实现和短测。
