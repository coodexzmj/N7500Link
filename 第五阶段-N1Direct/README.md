## 最终目标与固定架构

最终目标是让 Windows 和 iPhone 只作为控制终端，由 N1 独占 N7500 的蓝牙链路，完整替代原安卓 HT 软件的日常直连操作。

```text
Windows 浏览器 / iPhone Safari
              |
      家庭 Wi-Fi / Tailscale
              |
          N1Direct
              |
 Bluetooth Classic / RFCOMM / GAIA
              |
        WENNUO N7500
```

Windows 不使用电脑自带蓝牙直接连接 N7500；N1 始终是唯一建立 RFCOMM 会话、发送 GAIA 帧和管理通知的节点。浏览器只调用 N1 上的本地 HTTP API，不能直接发送蓝牙帧。

## 0.6.0 信道目录

网页新增“信道目录”页，固定展示 0..31 共 32 个信道。首次进入该页时，N1 会在当前蓝牙链路 epoch 内自动开始一次目录刷新；刷新按信道编号逐个串行读取，避免与当前信道读取和控制操作争用同一响应。

目录分为五个状态：

- `EMPTY`：尚未开始读取。
- `REFRESHING`：正在读取，页面每 900 ms 轮询进度。
- `COMPLETE`：32 项均在本轮成功读取。
- `PARTIAL`：本轮结束，但至少一项超时或报错。
- `OFFLINE`：N1 与 N7500 当前不可用，返回 503。

单个信道使用 `PENDING / OK / TIMEOUT / ERROR` 标记本轮结果。`OK` 且收发频率都为 `null` 表示已确认的空信道；失败项不会凭空补值，若此前有成功结果则保留旧值并设置 `stale=true` 和 `errorCode`。`PARTIAL` 保留最后一次失败原因，只有 `COMPLETE` 清空 `lastErrorCode`。

网页支持按编号、名称、频率、状态和错误码搜索，并显示：

- 两位信道编号。
- 名称。
- RX / TX MHz。
- 当前读取状态。
- 旧值过期标记和错误码。
- 最近读取或尝试时间。
- A、B 和当前信道标识。

手动刷新按钮在请求进行时禁用并防重复提交；同一次刷新正在运行时，重复 `POST` 也是幂等的。

## 0.6.0 目录接口

```text
GET  /api/v1/channels
GET  /api/v1/channels/{id}
POST /api/v1/channels/refresh
```

- 列表接口返回完整目录快照，即使状态为 `EMPTY` 或 `REFRESHING` 也返回 200。
- 单信道接口只读取缓存项，编号必须是 `0..31`；越界或整数溢出返回 400 `CHANNEL_OUT_OF_RANGE`，非数字路径返回 404。
- 刷新接口立即返回 202，用 `refreshEpoch` 标记本次链路；客户端随后轮询列表直到 `COMPLETE` 或 `PARTIAL`。
- 电台未连接时三个接口均返回 503 `RADIO_NOT_READY`。
- 目录读取不改变当前信道、频率、亚音、功率或其他电台设置。

完整字段和状态定义见 [HTTP API V1 合同](API-V1.yaml)，文档版本为 `OpenAPI 1.2.0`，业务 `schemaVersion` 仍为 `1`。

## 保留的三项低风险控制

本期没有扩大写入面，仍只有：

- 音量 `0..15`。
- 扫描开/关。
- 当前 A/B 信道侧切换。

每次写入继续执行“读取基线 → 一次目标写入 → 延迟回读 → 不一致时最多一次回滚”。扫描和 A/B 只修改完整设置块中的目标位，不允许部分设置块直接写入。网页必须二次确认，请求体必须包含 `confirm:true`。

`0.6.0` 没有重新执行这三项写入；其真实 N7500 闭环结果来自 `0.4.0`，作为未改变控制逻辑的回归基线。不能把历史结果写成 `0.6.0` 新执行的测试。

## 界面

### 安卓原生界面

原生界面保持 `0.5.0` 已实机验证的微信风格“单屏 + 固定左侧菜单”，五个页面为运行状态、蓝牙电台、网络设置、运行选项、网关与令牌。`0.6.0` 仅更新原生页脚版本，没有把网页目录塞回原生滚动页面。

### 远程网页

网页是微信风格响应式布局，当前页签为总览、直连控制、设备信息、当前信道、信道目录、网关状态、诊断和关于。页面全部使用本地 HTML、CSS、JavaScript，不加载 CDN、第三方统计或远程字体。

## 安全边界

- 同一时间只允许一个控制写操作。
- 蓝牙 Socket 只由 N1 的 `BluetoothLink` 持有。
- HTTP 线程不能直接构造或发送 GAIA 帧。
- 写入白名单仍只有 `WRITE_SETTINGS` 与 `SET_VOLUME`。
- 目录读取与当前信道读取使用独立请求来源，避免响应错配。
- 不提供 PTT、音频、频率/亚音/带宽直接写入、信道记录写入、固件升级和工厂复位。
- 不登录 HT 账号，不接入 HT 聊天室或 HT 云端服务器。
- 不监听 `0.0.0.0`，不做公网端口映射，不把 ADB 暴露给浏览器。
