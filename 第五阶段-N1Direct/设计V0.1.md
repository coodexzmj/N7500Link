## 1. 阶段目标

第五阶段在 `0.5.0` 已验证的受限直连控制上增加固定 `0..31` 信道目录只读能力，继续不进入音频和发射链路。功能按“先读取、再低风险写入、再配置编辑、最后音频与 PTT”的顺序扩展，长稳测试统一推迟到全部功能完成之后。

```text
电脑浏览器 / iPhone Safari
          |
    家庭 Wi-Fi 或 Tailscale
          |
 N1Direct 0.6.0
          |
 Bluetooth Classic / RFCOMM / GAIA
          |
     WENNUO N7500
```

本阶段继续只开放三项低风险写入，并新增网页只读信道目录：

- 音量 `0..15`。
- 扫描开/关。
- 当前 A/B 信道侧切换。

新增能力只读取 0..31 信道的名称与收发频率并缓存，不修改信道记录。频率、亚音、带宽、功率、信道记录写入、PTT、音频、固件和工厂操作仍全部关闭。N1 仍是唯一持有蓝牙 Socket 的执行节点；浏览器不能直接发送 GAIA 原始字节。

## 3. 范围边界

### 3.1 本期实现

- 0.3.8 只读网关能力的独立实现：前台服务、开机恢复、屏幕常亮、唯一蓝牙会话和自动重连。
- 只读快照、状态 revision、过期标记和 SSE 状态推送。
- 10 位访问令牌、HttpOnly 会话、Bearer/Cookie 鉴权、失败限流和脱敏审计。
- 微信风格桌面/移动网页，提供总览、直连控制、设备、当前信道、信道目录、网关、诊断和关于页签。
- 固定 `0..31` 信道目录只读状态机、自动/手动刷新、失败保留旧值和过期标记。
- `GET /api/v1/channels`、`GET /api/v1/channels/{id}`、`POST /api/v1/channels/refresh` 三个目录接口。
- 安卓原生主界面采用微信风格“单屏页面 + 左侧固定菜单”，五个页面在同一屏内切换。
- 音量、扫描、A/B 三项控制输入与显式二次确认。
- 写入前基线读取、单次写入、延迟回读、最多一次回滚。
- 只允许 `CMD_WRITE_SETTINGS` 和 `CMD_SET_VOLUME` 两条写命令。

### 3.2 明确不做

- 不做远程 PTT、语音采集、音频上传、音频播放或录音。
- 不做频率、亚音、带宽、功率写入。
- 不做信道记录写入、扫描信道表编辑或固件升级。
- 不做 HT 账号、HT 聊天室、HT 广播房间或 HT 云端服务器接入。
- 不绑定通配地址，不做公网端口映射，不把 ADB 暴露给浏览器。
- 不把“低风险写入验证”宣传为完整远程发射能力。

## 4. 软件结构

```text
MainActivity                 配对、令牌、日志与启停
GatewayService               前台服务、开机恢复、屏幕/CPU/Wi-Fi 锁
GatewayBootScheduler         开机任务调度
BootReceiver                 系统启动广播
RadioSession                 唯一蓝牙连接与链路 epoch
CommandScheduler             单队列、读取合并、写命令白名单
BluetoothLink                RFCOMM 收发线程
GaiaCodec                    GAIA 帧编解码与命令白名单
RadioParser                  设备信息、状态、音量、信道与设置解析
SettingsBlock                完整设置块复制与局部位修改
StatusRepository             不可变快照、revision、stale
LowRiskWriteController       单操作状态机、回读与回滚
ChannelCatalogService       0..31 信道目录只读状态机
LocalWebServer               HTTP 路由、鉴权、JSON 与 SSE
AuthManager                  令牌哈希、Cookie、会话与限流
SseHub                       SSE 客户端管理与心跳
```

HTTP 工作线程不直接调用 `BluetoothSocket`。所有蓝牙请求必须进入 `RadioSession`/`CommandScheduler`；目录读取通过 `ChannelCatalogService` 的固定信道读取来源进入同一调度器；写请求还必须经过 `LowRiskWriteController`。

## 5. 协议与命令白名单

GAIA 基础帧格式：

```text
FF 01 FLAGS LENGTH 00 02 CMD_HI CMD_LO [PAYLOAD...]
```

允许的读取命令：

```text
GET_DEV_INFO
REGISTER_NOTIFICATION
READ_SETTINGS
READ_RF_CH
GET_HT_STATUS
GET_VOLUME
```

允许的写入命令：

```text
WRITE_SETTINGS
SET_VOLUME
```

音量写入使用单字节参数 `0..15`。扫描和 A/B 不允许发送“只含目标字段”的部分设置，而是先复制完整 `READ_SETTINGS` 载荷，只修改对应标志位，再发送完整载荷；回读时必须与预期完整载荷逐字节一致。

### 5.1 只读信道目录

信道目录固定为 32 项，只读取信道 `0..31` 的名称和收发频率，不接受浏览器提供的信道载荷或原始命令。

```text
EMPTY -> REFRESHING -> COMPLETE
                     -> PARTIAL
任意状态 -- 链路不可用 --> OFFLINE
链路 epoch 改变 --> 清空目录并回到 EMPTY
```

保护规则：

- 首次已鉴权的列表请求在当前 epoch 内最多自动触发一次刷新。
- 手动刷新立即返回 202；同一代次刷新正在执行时，重复请求幂等。
- 32 个信道串行读取，同一时间只允许一个目录请求在途。
- 单项状态为 `PENDING / OK / TIMEOUT / ERROR`。
- `OK` 且收发频率都为 `null` 表示已确认的空信道。
- 读取失败不伪造新值；已有旧值时保留并标记 `stale=true` 与 `errorCode`。
- `PARTIAL` 保留最后一次失败原因，只有 `COMPLETE` 清空 `lastErrorCode`。
- 目录读取与普通当前信道读取使用独立来源，避免响应错配。
- 浏览器只能查询缓存和请求刷新，不能指定信道编号之外的任何读取参数。

## 6. 控制状态机

```text
ACCEPTED
  -> BASELINE_READ
  -> WRITING
  -> READBACK
  -> READBACK_OK
```

异常路径：

```text
已有操作未结束                 -> HTTP 409 CONTROL_BUSY
电台/链路未就绪                -> HTTP 503 RADIO_NOT_READY
基线无效或设备超时             -> TIMEOUT / UNAVAILABLE
写入后回读不一致               -> READBACK_MISMATCH -> 一次回滚
链路 epoch 变化                -> LINK_LOST / CANCELLED
```

保护参数：

- 每次操作总超时：12 秒。
- 回滚超时：8 秒。
- 回读延迟：900 毫秒。
- 单操作互斥：同一时间只允许一个控制请求。
- 写入命令不自动重试；回滚最多一次。
- 回滚只在基线已经成功读取且目标写入已尝试后执行。
- 操作结果通过 `GET /api/v1/control` 查询，页面轮询该状态直到进入终态。

## 7. HTTP 与鉴权

接口分为健康、登录、只读监控、信道目录和控制五组：

```text
GET    /healthz
GET    /login
POST   /api/v1/session
DELETE /api/v1/session
GET    /
GET    /assets/app.js
GET    /assets/style.css
GET    /api/v1/snapshot
GET    /api/v1/events
GET    /api/v1/channels
GET    /api/v1/channels/{id}
POST   /api/v1/channels/refresh
GET    /api/v1/control
POST   /api/v1/control/volume
POST   /api/v1/control/scan
POST   /api/v1/control/side
```

控制请求必须：

1. 使用 `Authorization: Bearer <token>` 或有效 HttpOnly Cookie。
2. 使用 `Content-Type: application/json`。
3. 请求体不超过 1024 字节。
4. 显式包含 `confirm:true`。
5. 参数只能是合同允许的取值范围。

音量请求示例：

```json
{"volume":4,"confirm":true}
```

扫描请求示例：

```json
{"scan":true,"confirm":true}
```

A/B 请求示例：

```json
{"side":"B","confirm":true}
```

## 8. 网络与安全边界

| 模式 | 默认 | 监听方式 | 说明 |
| --- | --- | --- | --- |
| 回环模式 | 是 | `127.0.0.1:8710` | 仅本机 |
| 局域网模式 | 否 | 手动选择单个 IPv4 地址 | 明文 HTTP，仅可信家庭网络 |
| Tailscale 模式 | 否 | 手动选择 Tailscale 地址 | 依赖隧道加密 |

安全规则：

- 不监听 `0.0.0.0`，不做公网端口映射。
- 令牌服务端只保存哈希，明文只在 N1 本地页面显示。
- 令牌不进入 URL、日志、SSE 或审计。
- Cookie 使用 HttpOnly、SameSite=Strict，会话默认 12 小时。
- 连续鉴权失败触发来源限流。
- 审计不保存完整 IP、完整 MAC、设备序列号、原始帧或请求正文。
- 页面不加载 CDN、第三方脚本、统计或远程字体。
- 快照带 `instanceId`、`revision`、`updatedAt`、`staleAfterMs` 和 `stale`。

## 9. 界面设计

### 9.1 安卓原生界面

N1 本地应用采用微信风格的绿色标题栏和固定左侧菜单，右侧使用 `FrameLayout` 页面容器，一次只显示一个功能页。左侧菜单固定为：

- 运行状态。
- 蓝牙电台。
- 网络设置。
- 运行选项。
- 网关与令牌。

五个页面在启动时构建并通过 `VISIBLE/GONE` 切换。选中菜单项使用绿色背景和白色文字，非选中项保持透明；菜单按钮同时支持点击与焦点导航。运行状态页占满右侧剩余高度。

界面不依赖上下滚动，不使用 `ScrollView`、`PositionStableScrollView`、上翻/下翻/到底按钮、鼠标滚轮处理或滚动位置锚点。目标实机分辨率为 1920×1080，要求上述五个页面均能在一屏内完整显示。后续增加内容时必须继续优先压缩或分页，不能重新引入滚动实现作为兜底。

### 9.2 远程网页

页面采用微信风格的绿色强调色和分栏卡片布局，顶部提供连接状态、当前信道和扫描状态。页签包括：

- 总览。
- 直连控制。
- 设备。
- 当前信道。
- 信道目录。
- 网关。
- 诊断。
- 关于。

直连控制页只出现三类写入操作。每项操作都有当前值、目标值、确认按钮和结果条；页面不会把“请求已接受”误写成“写入已成功”，而是在控制状态进入 `READBACK_OK` 后才显示成功。

信道目录页只读展示 32 个固定信道，支持按编号、名称、频率、状态和错误码搜索，并显示 A/B/当前信道标识、旧值过期标记、错误码和读取时间。刷新期间页面轮询进度并禁用重复提交。

## 10. 失败处理

| 情况 | 页面/接口行为 |
| --- | --- |
| 令牌错误 | 401，不区分令牌不存在或会话失效 |
| 令牌错误次数过多 | 429，短时停止登录 |
| 请求体过大 | 413 |
| 非 JSON 控制请求 | 415 |
| 缺少 `confirm:true` | 400 `CONFIRMATION_REQUIRED` |
| 参数越界 | 400 `VOLUME_OUT_OF_RANGE` / `SCAN_OUT_OF_RANGE` / `SIDE_OUT_OF_RANGE` |
| 信道编号越界或整数溢出 | 400 `CHANNEL_OUT_OF_RANGE` |
| 目录刷新未能启动 | 503 `CATALOG_REFRESH_FAILED` |
| 信道读取失败 | 单项标为 `TIMEOUT` / `ERROR`；有旧值则 `stale=true` |
| 已有控制操作 | 409 `CONTROL_BUSY` |
| 电台未就绪 | 503 `RADIO_NOT_READY` |
| 写入后回读不一致 | `READBACK_MISMATCH`，随后一次回滚 |
| 蓝牙或链路 epoch 改变 | `LINK_LOST` / `CANCELLED` |
| 回滚失败 | `ROLLBACK_FAILED`，必须保留错误并提示人工检查 |

## 11. 验收标准

### 11.1 离线门禁

- GAIA 编解码、半包/粘包、响应匹配和 epoch 失效测试通过。
- 写命令白名单只包含两条允许命令。
- 只读命令和只写路径不能被网页绕过。
- 状态机覆盖正常写入、回读不一致、超时和回滚。
- HTTP 鉴权、`confirm`、请求体上限、单操作互斥和错误码通过。
- 网页语法、版本号、控制控件和二次确认门禁通过。
- 目录门禁通过：三个路由、32 项固定边界、目录状态、搜索、A/B 标识、过期标识和移动布局齐全。`test.ps1` 共 155 项第五阶段检查通过。
- 原生界面结构门禁通过：固定左侧菜单、`FrameLayout` 页面容器和五个菜单名称齐全，源码不得重新出现 `ScrollView`、上翻/下翻/到底或滚动锚点实现。

### 11.2 历史实机回归基线

以下结果分别来自 0.5.0 和 0.4.0，不是 0.6.0 新执行的测试：

- 0.5.0 在真实 N1 上完成五个左侧菜单逐页切换，1920×1080 下每页完整显示且无上下滚动。
- 0.5.0 前台服务在线，HT 官方应用未运行，N7500 蓝牙连接正常。
- 0.4.0 音量执行 `原值 -> 新值 -> 回读 -> 原值`，`READBACK_OK`。
- 0.4.0 扫描执行 `关闭 -> 打开 -> 回读 -> 关闭`，`READBACK_OK`。
- 0.4.0 A/B 执行 `A -> B -> 回读 -> A`，`READBACK_OK`。
- 上述控制逻辑、写白名单和回滚状态机在 0.6.0 中没有扩大；0.6.0 未重做三项写入。

## 12. 风险与后续门槛

| 风险 | 应对 |
| --- | --- |
| 明文局域网 HTTP | 默认回环，外部模式只使用可信网络或 Tailscale |
| 多客户端误操作 | 单操作互斥、显式确认、状态查询和审计 |
| 设置块部分写入导致参数漂移 | 完整设置块复制、只改目标位、全载荷回读 |
| 回读延迟不足 | 延迟读取、超时和最多一次回滚 |
| 链路重建导致旧响应污染 | `instanceId`、revision 与链路 epoch；目录随 epoch 清空 |
| 32 信道读取耗时较长 | 串行按需刷新、进度轮询、同代次幂等，不阻塞控制写操作 |
| 单信道失败被误当空信道 | 独立 `TIMEOUT/ERROR`、`stale` 与 `errorCode`；只有 `OK + null` 才是空信道 |
| N1 熄屏断网 | 前台服务、屏幕常亮、CPU/Wi-Fi 锁 |
| 把直连控制误当成 PTT 能力 | 文档、页面和 API 都明确禁止发射与音频 |

所有单项功能测试继续控制在 5 分钟以内；两小时常稳、N7500 断电重连、实际电脑/iPhone/Tailscale 页面、多人并发、50 次写入和 100 次 PTT 统一放到全部功能完成后的最后阶段。远程 PTT 必须另行设计本地急停、断线释放和最大发射超时，未完成前不得开放可点击控件。

## 13. 结论

0.6.0 在 0.5.0 已验证的直连控制边界上增加固定 0..31 信道目录只读能力，网页可搜索并观察逐项读取状态，但不会修改信道记录。控制写白名单和回滚逻辑没有扩大；0.4.0 的真实 N7500 三项控制闭环仍是回归基线。0.6.0 已完成离线验证、真实 N1 覆盖安装、前台服务和接口边界检查；由于测试时 N7500 未在线，真实 32 项目录仍待复测。该版本不是完整 HT 替代版本，也不是远程发射版本。
