## 项目总设计方案

### 1. 项目目标

让斐讯 N1 直接通过系统蓝牙连接和控制 WENNUO N7500，逐步摆脱 HT 手机版、HT 账号、HT 聊天室和 HT 云端服务器的依赖，并让电脑和 iPhone 通过可信私有网络查看状态，后续再按安全门槛扩展远程控制与音频能力。

最终目标：

- N7500 保持原有硬件，不修改电台固件。
- N1 是唯一的蓝牙执行节点。
- 电脑和 iPhone 只作为查看或控制终端。
- 不使用 HT 账号、HT 频道口令或 HT 官方服务器。
- 优先使用家庭 Wi-Fi 和 Tailscale，不把蓝牙或 ADB 暴露到公网。
- 长期无人值守时，断线可恢复、状态可观测、异常可追溯。
- 任何发射能力都必须具备本地急停、断线释放、超时释放和实机验收。

### 2. 总体架构

```text
iPhone Safari / Windows PC
          |
    家庭 Wi-Fi / Tailscale
          |
    N1 常驻网关服务
          |
 Bluetooth Classic / RFCOMM / GAIA
          |
      WENNUO N7500
```

N1 是唯一持有蓝牙 Socket 的设备。网页、电脑和手机不直接连接电台，也不能绕过网关向蓝牙发送原始字节。

### 3. 设计原则

1. **先只读，后写入**：先证明状态读取、长连接、鉴权、缓存和断线恢复可靠，再开放任何写操作。
2. **先低风险，后发射**：音量、扫描、A/B 切换完成回读和稳定性验收后，才评审远程写入；PTT 和音频独立设计。
3. **单一执行节点**：同一时间只允许一个 `RadioSession` 和一个 GAIA 请求在途，避免响应错配。
4. **默认关闭外部访问**：网关默认只监听回环地址；局域网或 Tailscale 模式必须本地手动开启。
5. **不使用 HT 身份**：网关令牌与 HT 账号、频道口令和聊天室完全独立。
6. **旧值必须标记过期**：页面必须区分“最后已知值”和“实时值”，不能把断线前快照冒充当前状态。
7. **每个阶段可独立安装**：不同阶段使用不同包名或独立工程，避免新功能破坏已经验证的版本。
8. **每个阶段完成即发布**：阶段达到验收条件后提交并推送 GitHub；设计或验收结论发生变化时，同步更正本页和对应阶段文档。

### 5. 当前软件结构

```text
N7500Link 仓库
├─ 第一阶段-N1Probe / 根目录探针源码
│    └─ 只读 GAIA 命令验证
├─ 第二阶段-N1Control
│    ├─ 蓝牙连接与 GAIA 编解码
│    ├─ 只读快照
│    ├─ 音量写入与主动回读
│    ├─ 扫描和 A/B 设置写入
│    └─ 单写锁、在途命令互斥与回滚
├─ 第三阶段-N1Gateway
│    ├─ GatewayService      前台服务与开机恢复
│    ├─ RadioSession        唯一蓝牙连接入口
│    ├─ CommandScheduler    串行只读命令与合并
│    ├─ StatusRepository    实例、revision 与过期快照
│    ├─ LocalWebServer      HTTP JSON 与 SSE
│    ├─ AuthManager         独立令牌、Cookie 与限流
│    └─ AuditStore          脱敏审计
└─ 第四阶段-N1RemoteControl
     ├─ GatewayService      独立包名前台服务与开机恢复
     ├─ LowRiskWriteController  单操作状态机与一次回滚
     ├─ GaiaCodec           写入白名单与完整设置块保护
     ├─ LocalWebServer       登录、快照、SSE 与三项控制接口
     ├─ 微信风格网页          总览、控制、设备、信道、网关和诊断
     └─ Test-Live*.ps1       脱敏实机登录与受限写入验证工具
```

第二阶段不包含网络权限；第三阶段首次申请 `INTERNET` 权限，但只用于回环、家庭局域网或 Tailscale 监听。第四阶段继续使用独立网络服务，但写命令白名单只允许 `SET_VOLUME` 和完整设置块 `WRITE_SETTINGS`，应用层只开放音量、扫描、A/B 三项。PTT、音频、频率/亚音/带宽、信道记录和固件能力继续禁止。

N1 固件在整机休眠时会断开 Wi-Fi，因此 0.3.5 起默认保持屏幕常亮，同时持有部分 CPU 唤醒锁和高性能 Wi-Fi 锁；停止服务时成对释放。第四阶段沿用该保活策略。用户仍可手动关闭屏幕常亮，但关闭后不能保证远程常驻。

### 6. 当前协议基线

N7500 使用 Bluetooth Classic / RFCOMM，当前已验证标准 SDP 自动信道连接。GAIA 帧格式：

```text
FF 01 FLAGS LENGTH 00 02 CMD_HI CMD_LO [PAYLOAD...]
```

已实机确认的关键数据：

| 项目 | 结果 |
| --- | --- |
| 产品 ID | `0x0008` |
| 软件版本 | `0x0092` |
| 信道数 | 32 |
| 区域数 | 6 |
| 频段段数 | 3 |
| FM 广播接收 | 支持 |
| DMR | 不支持 |
| VFO | 不支持 |
| 当前基线 | A 信道 1、B 信道 4 |
| 扫描 | 关闭 |
| 静噪 | 1 |

DMR 不在当前项目范围内。仓库不保留语音解码功能代码或后续承诺。

### 7. 第三阶段 G1 设计结论

第三阶段第一版只做**远程只读监控**：

```text
N1Gateway
  → Bluetooth RFCOMM
  → N7500
  → 只读快照
  → HTTP JSON / SSE
  → PC / iPhone
```

G1 明确禁止：

- 远程 PTT、音频上传、音频播放或录音。
- 远程音量、扫描、信道 A/B 或频率写入。
- 信道记录写入、固件升级或工厂复位。
- HT 账号、聊天室或官方服务器。
- 公网端口映射。
- 监听 `0.0.0.0`。

第一版接口只有：

```text
GET  /healthz
GET  /login
POST /api/v1/session
DELETE /api/v1/session
GET  /
GET  /assets/app.js
GET  /assets/style.css
GET  /api/v1/snapshot
GET  /api/v1/events
```

不注册 `POST /ptt`、`POST /volume`、`POST /scan`、`POST /channel`、`PUT /settings` 或 `POST /firmware`。

详细合同见 [第三阶段 API-V1.yaml](第三阶段-N1Gateway/API-V1.yaml)。

### 8. 网络与安全边界

| 模式 | 默认 | 监听方式 | 说明 |
| --- | --- | --- | --- |
| 回环模式 | 是 | `127.0.0.1:8710` | 仅本机访问 |
| 局域网模式 | 否 | 手动选择一个 IPv4 地址 | HTTP 明文，仅可信家庭网络 |
| Tailscale 模式 | 否 | 手动选择 Tailscale 地址 | 依赖 Tailscale 隧道加密 |

安全规则：

- 不绑定 `0.0.0.0`，不做公网端口映射。
- 外部模式必须有独立访问令牌，并默认 12 小时会话。
- 令牌只保存哈希，不出现在 URL、日志或 SSE 数据中。
- Cookie 使用 HttpOnly、SameSite=Strict。
- 连续鉴权失败触发来源限流。
- 审计不保存令牌、Cookie、完整 IP、完整 MAC、设备序列号或原始帧。
- 页面不加载 CDN、第三方脚本、统计或远程字体。
- 快照必须带 `instanceId`、`revision`、`updatedAt`、`staleAfterMs` 和 `stale`。

### 9. 发射与音频门槛

在满足以下全部条件前，不进入远程 PTT：

- 本地音频接收和发射链路稳定。
- 蓝牙断线、网络断线和进程退出都能立即释放 PTT。
- 具备硬件或软件本地急停。
- 具备最大发射超时。
- 合法频率、合适假负载和受控测试环境。
- 完成 100 次 PTT 按下/释放及异常断线验收。

第三阶段 G1 和第二阶段的低风险写入都不能直接扩展成远程发射。

### 10. 验收与发布纪律

每个阶段只有在文档、代码、安装包、校验值和验收结论一致后才提交。每次阶段完成都执行一次 GitHub 推送，并在本页更新状态。

已经确立的发布要求：

1. 安装包、源码、构建脚本和安装说明放在同一阶段目录。
2. SHA-256 必须与安装包一致。
3. 离线自测、实机检查和待验收项目必须分开描述。
4. 不得把“能连接”描述成“完整验收通过”。
5. 不得提交真实局域网 IP、完整蓝牙 MAC、序列号、令牌或调试日志原文。
6. 调试签名必须明确标注，不得冒充正式发布证书。

## 当前限制

N1 固件熄屏后会进入整机深度休眠并断开 Wi-Fi。当前没有可用的远程唤醒通路，因此 N1 一旦熄屏只能等待现场重新上电或唤醒。0.4.1 默认保持屏幕常亮，是当前 N1 固件条件下的无人值守方案；长稳结论必须重新以当前软件基线完成监测后才有效。

0.4.1 的界面改造不改变 0.4.0 已验证的三项低风险控制范围；本版没有重新证明音频链路、PTT 安全释放或长期无人值守能力。
