# N7500Link 第四阶段设计：N1 受限远程控制

文档版本：V0.1（0.4.1 修订）

设计日期：2026-11-28

作者署名：BI4BYF

文档状态：现行设计；0.4.1 已按本设计完成安卓原生单屏界面实现、离线门禁和真实 N1 上机验证，并沿用 0.4.0 已完成的 N7500 控制链路验证。

上位文档：[项目总设计方案（仓库主页）](../README.md)

## 1. 阶段目标

第四阶段把第三阶段已验证的 N1 常驻只读网关推进到“受限远程控制”，但不进入音频和发射链路。

```text
电脑浏览器 / iPhone Safari
          |
    家庭 Wi-Fi 或 Tailscale
          |
 N1RemoteControl 0.4.1
          |
 Bluetooth Classic / RFCOMM / GAIA
          |
     WENNUO N7500
```

本阶段只开放三项低风险设置：

- 音量 `0..15`。
- 扫描开/关。
- 当前 A/B 信道侧切换。

频率、亚音、带宽、功率、信道记录、PTT、音频、固件和工厂操作仍全部关闭。N1 仍是唯一持有蓝牙 Socket 的执行节点；浏览器不能直接发送 GAIA 原始字节。

## 3. 范围边界

### 3.1 本期实现

- 0.3.8 只读网关能力的独立实现：前台服务、开机恢复、屏幕常亮、唯一蓝牙会话和自动重连。
- 只读快照、状态 revision、过期标记和 SSE 状态推送。
- 10 位访问令牌、HttpOnly 会话、Bearer/Cookie 鉴权、失败限流和脱敏审计。
- 微信风格桌面/移动网页，提供总览、远程控制、设备、信道、网关、诊断和关于页签。
- 安卓原生主界面采用微信风格“单屏页面 + 左侧固定菜单”，五个页面在同一屏内切换。
- 音量、扫描、A/B 三项控制输入与显式二次确认。
- 写入前基线读取、单次写入、延迟回读、最多一次回滚。
- 只允许 `CMD_WRITE_SETTINGS` 和 `CMD_SET_VOLUME` 两条写命令。

### 3.2 明确不做

- 不做远程 PTT、语音采集、音频上传、音频播放或录音。
- 不做频率、亚音、带宽、功率写入。
- 不做信道记录写入、扫描信道表编辑或固件升级。
- 不做 HT 账号、HT 聊天室、HT 广播房间或 HT 云端服务器接入。
- 不绑定通配地址，不做公网端口映射，不把 ADB 暴露给浏览器。
- 不把“低风险写入验证”宣传为完整远程发射能力。

## 4. 软件结构

```text
MainActivity                 配对、令牌、日志与启停
GatewayService               前台服务、开机恢复、屏幕/CPU/Wi-Fi 锁
GatewayBootScheduler         开机任务调度
BootReceiver                 系统启动广播
RadioSession                 唯一蓝牙连接与链路 epoch
CommandScheduler             单队列、读取合并、写命令白名单
BluetoothLink                RFCOMM 收发线程
GaiaCodec                    GAIA 帧编解码与命令白名单
RadioParser                  设备信息、状态、音量、信道与设置解析
SettingsBlock                完整设置块复制与局部位修改
StatusRepository             不可变快照、revision、stale
LowRiskWriteController       单操作状态机、回读与回滚
LocalWebServer               HTTP 路由、鉴权、JSON 与 SSE
AuthManager                  令牌哈希、Cookie、会话与限流
SseHub                       SSE 客户端管理与心跳
```

HTTP 工作线程不直接调用 `BluetoothSocket`。所有蓝牙请求必须进入 `RadioSession`/`CommandScheduler`，写请求还必须经过 `LowRiskWriteController`。

## 5. 协议与命令白名单

GAIA 基础帧格式：

```text
FF 01 FLAGS LENGTH 00 02 CMD_HI CMD_LO [PAYLOAD...]
```

允许的读取命令：

```text
GET_DEV_INFO
REGISTER_NOTIFICATION
READ_SETTINGS
READ_RF_CH
GET_HT_STATUS
GET_VOLUME
```

允许的写入命令：

```text
WRITE_SETTINGS
SET_VOLUME
```

音量写入使用单字节参数 `0..15`。扫描和 A/B 不允许发送“只含目标字段”的部分设置，而是先复制完整 `READ_SETTINGS` 载荷，只修改对应标志位，再发送完整载荷；回读时必须与预期完整载荷逐字节一致。

## 6. 控制状态机

```text
ACCEPTED
  -> BASELINE_READ
  -> WRITING
  -> READBACK
  -> READBACK_OK
```

异常路径：

```text
已有操作未结束                 -> HTTP 409 CONTROL_BUSY
电台/链路未就绪                -> HTTP 503 RADIO_NOT_READY
基线无效或设备超时             -> TIMEOUT / UNAVAILABLE
写入后回读不一致               -> READBACK_MISMATCH -> 一次回滚
链路 epoch 变化                -> LINK_LOST / CANCELLED
```

保护参数：

- 每次操作总超时：12 秒。
- 回滚超时：8 秒。
- 回读延迟：900 毫秒。
- 单操作互斥：同一时间只允许一个控制请求。
- 写入命令不自动重试；回滚最多一次。
- 回滚只在基线已经成功读取且目标写入已尝试后执行。
- 操作结果通过 `GET /api/v1/control` 查询，页面轮询该状态直到进入终态。

## 7. HTTP 与鉴权

接口分为健康、登录、只读监控和控制四组：

```text
GET    /healthz
GET    /login
POST   /api/v1/session
DELETE /api/v1/session
GET    /
GET    /assets/app.js
GET    /assets/style.css
GET    /api/v1/snapshot
GET    /api/v1/events
GET    /api/v1/control
POST   /api/v1/control/volume
POST   /api/v1/control/scan
POST   /api/v1/control/side
```

控制请求必须：

1. 使用 `Authorization: Bearer <token>` 或有效 HttpOnly Cookie。
2. 使用 `Content-Type: application/json`。
3. 请求体不超过 1024 字节。
4. 显式包含 `confirm:true`。
5. 参数只能是合同允许的取值范围。

音量请求示例：

```json
{"volume":4,"confirm":true}
```

扫描请求示例：

```json
{"scan":true,"confirm":true}
```

A/B 请求示例：

```json
{"side":"B","confirm":true}
```

## 8. 网络与安全边界

| 模式 | 默认 | 监听方式 | 说明 |
| --- | --- | --- | --- |
| 回环模式 | 是 | `127.0.0.1:8710` | 仅本机 |
| 局域网模式 | 否 | 手动选择单个 IPv4 地址 | 明文 HTTP，仅可信家庭网络 |
| Tailscale 模式 | 否 | 手动选择 Tailscale 地址 | 依赖隧道加密 |

安全规则：

- 不监听 `0.0.0.0`，不做公网端口映射。
- 令牌服务端只保存哈希，明文只在 N1 本地页面显示。
- 令牌不进入 URL、日志、SSE 或审计。
- Cookie 使用 HttpOnly、SameSite=Strict，会话默认 12 小时。
- 连续鉴权失败触发来源限流。
- 审计不保存完整 IP、完整 MAC、设备序列号、原始帧或请求正文。
- 页面不加载 CDN、第三方脚本、统计或远程字体。
- 快照带 `instanceId`、`revision`、`updatedAt`、`staleAfterMs` 和 `stale`。

## 9. 界面设计

### 9.1 安卓原生界面

N1 本地应用采用微信风格的绿色标题栏和固定左侧菜单，右侧使用 `FrameLayout` 页面容器，一次只显示一个功能页。左侧菜单固定为：

- 运行状态。
- 蓝牙电台。
- 网络设置。
- 运行选项。
- 网关与令牌。

五个页面在启动时构建并通过 `VISIBLE/GONE` 切换。选中菜单项使用绿色背景和白色文字，非选中项保持透明；菜单按钮同时支持点击与焦点导航。运行状态页占满右侧剩余高度。

界面不依赖上下滚动，不使用 `ScrollView`、`PositionStableScrollView`、上翻/下翻/到底按钮、鼠标滚轮处理或滚动位置锚点。目标实机分辨率为 1920×1080，要求上述五个页面均能在一屏内完整显示。后续增加内容时必须继续优先压缩或分页，不能重新引入滚动实现作为兜底。

### 9.2 远程网页

页面采用微信风格的绿色强调色和分栏卡片布局，顶部提供连接状态、当前信道和扫描状态。页签包括：

- 总览。
- 远程控制。
- 设备。
- 信道。
- 网关。
- 诊断。
- 关于。

远程控制页只出现三类操作。每项操作都有当前值、目标值、确认按钮和结果条；页面不会把“请求已接受”误写成“写入已成功”，而是在控制状态进入 `READBACK_OK` 后才显示成功。

## 10. 失败处理

| 情况 | 页面/接口行为 |
| --- | --- |
| 令牌错误 | 401，不区分令牌不存在或会话失效 |
| 令牌错误次数过多 | 429，短时停止登录 |
| 请求体过大 | 413 |
| 非 JSON 控制请求 | 415 |
| 缺少 `confirm:true` | 400 `CONFIRMATION_REQUIRED` |
| 参数越界 | 400 `VOLUME_OUT_OF_RANGE` / `SCAN_OUT_OF_RANGE` / `SIDE_OUT_OF_RANGE` |
| 已有控制操作 | 409 `CONTROL_BUSY` |
| 电台未就绪 | 503 `RADIO_NOT_READY` |
| 写入后回读不一致 | `READBACK_MISMATCH`，随后一次回滚 |
| 蓝牙或链路 epoch 改变 | `LINK_LOST` / `CANCELLED` |
| 回滚失败 | `ROLLBACK_FAILED`，必须保留错误并提示人工检查 |

## 11. 验收标准

### 11.1 离线门禁

- GAIA 编解码、半包/粘包、响应匹配和 epoch 失效测试通过。
- 写命令白名单只包含两条允许命令。
- 只读命令和只写路径不能被网页绕过。
- 状态机覆盖正常写入、回读不一致、超时和回滚。
- HTTP 鉴权、`confirm`、请求体上限、单操作互斥和错误码通过。
- 网页语法、版本号、控制控件和二次确认门禁通过。
- 原生界面结构门禁通过：固定左侧菜单、`FrameLayout` 页面容器和五个菜单名称齐全，源码不得重新出现 `ScrollView`、上翻/下翻/到底或滚动锚点实现。

### 11.2 实机门禁

- N1 前台服务在线，屏幕保持常亮，HT 官方应用未运行。
- 登录、页面、快照和 SSE 正常。
- 音量执行 `原值 -> 新值 -> 回读 -> 原值`。
- 扫描执行 `关闭 -> 打开 -> 回读 -> 关闭`。
- A/B 执行 `A -> B -> 回读 -> A`。
- 每一步都必须 `READBACK_OK`，最终状态恢复到原始值。
- 真实 N1 上五个左侧菜单逐页点击切换通过，1920×1080 下每页完整显示且无上下滚动。
- 旧上翻、下翻、到底入口不存在，原生页脚显示当前版本 0.4.1。
- 不执行 PTT、音频或频率/信道参数写入。

## 12. 风险与后续门槛

| 风险 | 应对 |
| --- | --- |
| 明文局域网 HTTP | 默认回环，外部模式只使用可信网络或 Tailscale |
| 多客户端误操作 | 单操作互斥、显式确认、状态查询和审计 |
| 设置块部分写入导致参数漂移 | 完整设置块复制、只改目标位、全载荷回读 |
| 回读延迟不足 | 延迟读取、超时和最多一次回滚 |
| 链路重建导致旧响应污染 | `instanceId`、revision 与链路 epoch |
| N1 熄屏断网 | 前台服务、屏幕常亮、CPU/Wi-Fi 锁 |
| 把低风险控制误当成 PTT 能力 | 文档、页面和 API 都明确禁止发射与音频 |

进入第五阶段前，至少需要完成两小时常稳、N7500 断电重连、实际电脑/iPhone/Tailscale 页面、多人并发和三操作重复稳定性验证。远程 PTT 必须另行设计本地急停、断线释放、最大发射超时和 100 次受控验收。

## 13. 结论

0.4.1 在 0.4.0 的低风险控制边界上完成安卓原生单屏重排，避免继续依赖上下滚动，并把五个功能页统一到固定左侧菜单。控制服务、写白名单和回滚逻辑没有扩大；0.4.0 的真实 N7500 三项控制闭环仍是当前控制逻辑的回归基线。该版本仍不是远程发射版本。
